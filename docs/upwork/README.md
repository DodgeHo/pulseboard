# Upwork Portfolio Surface

This folder documents the English-only portfolio surface generated by the portal build.

## Routes

- `/upwork/` is the focused entry page.
- `/upwork/feature-delivery/` is the React/Node feature delivery case study and browser demo.
- `/upwork/ai-code-rescue/` is the AI-generated code rescue case study and deterministic code-review demo.
- `/upwork/backend-reliability/` is the backend/reliability case study and explicit recovery simulation.

The demos are deliberately self-contained. They do not require an OpenAI API key, customer credentials, a database, Redis, or a cloud account.

## Visual assets

Static images live in `apps/portal/src/upwork/assets/`. When `ANLAN_INCLUDE_UPWORK=true`, `apps/portal/scripts/build.mjs` copies every file in that directory to `upwork/assets/` in both `apps/portal/dist` and `deploy/anlan`, so pages can reference `/upwork/assets/<file>` with absolute paths. The local preview server (`scripts/preview-public-surface.mjs`) serves these with correct image content types.

Asset sources:

- `tile-*.png` are the three overview thumbnails: real demo screenshots composed into browser-window frames with callout badges.
- `concept-*.jpg` are AI-generated, text-free concept illustrations (delivery board, code repair, protected backend) used as cover imagery.
- `planner-annotated.png`, `rescue-annotated.png`, and `recovery-visual.png` are layperson-friendly product renders composed from real demo screenshots with callouts and icons.
- `feature-planner-demo.png`, `feature-error-state.png`, `rescue-repair-demo.png`, and `reliability-simulation-demo.png` are real screenshots of the three browser demos captured with Playwright.
- `*.svg` files are denser engineering diagrams, kept in a secondary "Engineering diagrams" section near the end of each case page.

The render pipeline (demo-state capture plus HTML composition) is not part of the repository build; it lives outside the repo and writes its PNG/JPEG outputs into this assets directory. To regenerate: start the preview server, capture the demo states with Playwright, compose them in the HTML templates, and screenshot at 2x. Every `<img>` on the Upwork pages carries factual alt text and states representative-demo or simulation boundaries in its caption or surrounding copy.

## Evidence boundary

The feature and code-rescue pages show representative delivery methods. The backend page uses existing PulseBoard evidence where available and labels the interactive runbook as simulation. PulseBoard remains a production-shaped portfolio project rather than a claimed commercial production system.

No client name, customer result, usage metric, revenue figure, team size, delivery promise, or production deployment status is added by this portfolio surface.
