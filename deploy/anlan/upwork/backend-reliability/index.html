03 / Explicit reliability simulation

Strengthen the backend and reliability

Make APIs, data, background work, and recovery paths easier to trust.

Simulation only. It does not touch a database, queue, cloud account, or production service.

Problem

A backend is more than a happy-path endpoint. Reviewers need to see authentication boundaries, durable state, worker behavior, readiness signals, and what a recovery or rollback rehearsal can actually prove.

Approach

PulseBoard is the real evidence anchor: a production-shaped portfolio project with a Hono API, PostgreSQL and Prisma, Redis and BullMQ, API-key boundaries, OpenAPI, liveness/readiness, worker recovery, and local backup/restore and rollback rehearsals.

Proof

The demo below is an explicit simulation of an operational runbook. It walks through health checks, queue retry, a restore gate, and rollback verification so the distinction between a documented procedure and a live production claim stays visible.

Limits

The simulation is not a live incident system and does not establish production traffic, SLA, RPO/RTO, or a successful remote deployment. AWS remains plan-only in the current evidence boundary.
